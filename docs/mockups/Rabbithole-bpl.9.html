Board polish: the tutor draws small pictures live on the board, stroke by stroke

Rabbithole-bpl.9. The tutor makes a small picture on the board: a drawing op sets a box, and each path op adds one SVG path, drawn stroke by stroke with its fill fading in after, in colour names the theme maps to its own tokens. Spec: docs/board-polish-spec.md (Drawing component), ADR 0030. The spec wins where they differ.

  • Sizes are board units on the fixed 1600×900 board. Text, arrows, pointer, pen and spotlight are Rabbithole-bsk.3 and bsk.6's.
  • Path coordinates are the drawing's own 0-100 on both axes. The square scales uniformly by the box's smaller side and centres in the box, like an SVG viewBox that meets.
  • Strokes are 6 board units at any scale, like other marker strokes, round caps and joins. A fill is its colour role at 35% over the board surface.
  • Each path strokes along its direction, then fades its fill in over about 200 ms, overlapping the next path's stroke. A path takes about a box's length (draw-first, Rabbithole-bpl.3).
  • ink= and fill= accept blue, green, pink, yellow (the family hues), ink (text-primary) and muted (text-secondary). Anything else is a parse error. The drawing carries no raw colour values and re-tints on a theme switch.
  • At most 24 paths per drawing; the prompt asks for about 12. Drawings are written live in the reply and never taken from the piece library (ADR 0030).
  • The drawing has no frame, panel or background of its own: it sits on the board surface like a hand drawing.
  • Captions show the sentence being spoken. Frames read left to right, top to bottom. Dashed boxes are mockup markers only.

2. Stroke by stroke, then fill

The drawing op draws nothing visible; it sets the box. Each path draws its stroke along its own direction, then its fill fades in over about 200 ms while the next path starts. A path takes about a box's length, so a dozen paths still finish early in their sentences.

> Let's draw a plant.
dr drawing at 470,450 w=620 h=620
> A pot.
p1 path "M26 64H74V72H26Z" ink=ink fill=pink in dr
p2 path "M30 72H70L64 96H36Z" ink=ink fill=pink in dr
> A stem with three leaves.
p3 path "M50 64C50 52 48 40 50 26" ink=green in dr
p4 path "M49 50C38 48 28 40 25 31C36 31 46 38 49 50Z" ink=green fill=green in dr
…
p11 path "M8 96H92" ink=muted in dr

Op names and arguments are the spec's; the op parser owns their exact syntax.

3. Six colour names, all theme roles

ink= and fill= take only these six names. Each is a role mapped to a theme token, so a theme may render pink as purple; the rendered drawing has no raw colour values and re-tints on a theme or appearance switch. fill= may be left out for no fill. The swatches show stroke and 35% fill; switch to Light at the top to see the light tokens.

4. Reaching the drawing

The whole drawing is the unit the spotlight and the pen usually reach. Each path is also a board item, so the tutor can point at one path and the spotlight lights it alone.

5. Odd boxes and bad paths

A drawing box of any shape keeps the picture's proportions. Path data may hold only the SVG path commands M L H V C S Q T A Z (either case), numbers, spaces and commas, within a length limit. A path with anything else, an unknown colour name, a missing parent or a 25th path in one drawing is skipped and logged, and the board keeps going.

p5 path "M51 42 url(x)" ink=green fill=green in dr   ← skipped, logged: not path data
p12 path "M0 0H10" ink=red in dr                    ← skipped, logged: unknown colour "red"
