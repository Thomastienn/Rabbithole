# The tutor marks its notes inline in the reply text

ADR 0013 moved the tutor's notes and verdict into one `record_turn` call after the reply text. Every tool result starts another model response, and Claude Code asks for a visible answer after an empty one, so the tutor often wrote its whole reply again, `show_visual` call included, which drew a second identical visual and kept the run going 5 to 12 seconds longer. Suggestions and groundwork appeared only once the reply and the call were done, yet the learner needs a suggestion midway through reading, and groundwork before the text. Handing every note to the quick thinking model after the reply took about 15 seconds, mostly starting a model process and writing about 550 tokens. We decided that the tutor writes the notes the learner sees as plain double-bracket markers in its own text, the same for every provider: a `[[groundwork: …]]` line before any text, `[[term]]` around each suggestion where it is written, and an end section of `[[next: …]]` lines that is present even when empty. The server strips the markers as they stream, so groundwork shows as the reply begins, each underline appears with its term and next questions follow about a second after the text. The end section is the reply's last word: the server runs any calls left in that model response, then ends the reply and stops the tutor's run, so no further round can repeat it. Quick thinking writes the hidden notes in the background: the concept each suggestion names, the reply's concepts and links, and the verdict; for a reply that ends without an end section, it also marks suggestions, groundwork and next questions. `record_turn` is removed. We accepted a text format the tutor must follow again, a lost note wherever a tutor misplaces a marker, and usage read from each model message because a stopped run reports no final summary, in exchange for notes that arrive while the learner reads, one tutor prompt for every provider and no repeated answers.

This supersedes the part of ADR 0013 that returns the verdict and notes through a tutor tool call, and the part of ADR 0008 that has the tutor record concepts and links. The tutor still marks suggestions and next questions (ADR 0008); media calls stay tool calls (ADR 0013). ADR 0008 rejected inline markers because they could leak into copied text; the server now strips every marker before a reply is shown or stored.

## Considered Options

- Keep `record_turn` and drop the repeated answer. Done first; it hid the repeat but kept its delay, and the notes still waited for the whole reply.
- Quick thinking writes every note after the reply. One small tutor prompt, but about 15 seconds before the first underline.
- Quick thinking marks each section while the reply streams. Underlines trail the reading by a few seconds, at one extra call per section, from a weaker model.
- Inline markers for strong models and tool calls for the rest. Rejected: every provider behaves the same.
- Markdown links to a special target, such as `[fission](#s)`. Models write links reliably, but they collide with real links and render as links if stripping ever fails.
