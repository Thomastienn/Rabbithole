# Markers carry visuals and discussions; videos stay tool calls

ADR 0017 had the tutor write `[[visual: name]]` where a visual goes and call `show_visual` with the same name; a marker with no call was removed. Models write the marker and skip the call: on 2026-11-20 a Claude Sonnet reply about fusion lost its visual this way and left a blank gap, and in a Claude Haiku benchmark the tutor called the tool for 1 of 12 visual-worthy prompts while writing a marker for 10 of them. Marker-only prompts requested all 12, wrote no malformed marker, and used fewer input tokens and requests, because no tool result starts another model response. `start_discussion` showed the same pattern: its tool rejections cost up to four requests per reply, and in 3 of 4 runs the tutor kept writing after the call although the result told it to stop. We decided that a visual and a discussion are each requested by one marker line that carries every field the tool took, `[[visual: name | title: … | shows: … | alt: … | check: …]]` and `[[discussion: classmates… | opening lines…]]`, and that `show_visual` and `start_discussion` are removed. A visual starts drawing when its marker closes in the stream. A discussion marker is the reply's last word before the end section: text after it is dropped. With no tool there is no error to fix, so the server repairs what it can: a field over its limit is cut to the limit, a missing title or alt falls back to the name or what the visual shows, extra discussion lines are cut, and a marker it cannot use is dropped and logged, never shown, so a broken marker cannot reveal a check's hidden answer. `make_video` stays a tool call: markers changed nothing for videos in the benchmark, videos are rare and costly, and the validation feedback is worth the extra request. We accepted fields that cannot hold `[`, `]`, `|` or a line break, and silent repairs in place of the model correcting itself, in exchange for visuals and discussions that arrive whenever the tutor means them, at lower cost, the same on every provider.

This supersedes the parts of ADR 0013 that send visuals and discussions through tool calls and the part of ADR 0017 that pairs each marker with a `show_visual` call. Videos still go through tool calls (ADR 0013), and the marker still places its visual (ADR 0017).

## Considered Options

- Keep the tool and log orphan markers. Cheapest, but visuals keep going missing.
- Keep the tool and have quick thinking fill in an orphan marker's fields after the reply. Saves the visual, but it starts late, from a weaker model.
- Move `make_video` to a marker as well. One format for all media, but it gained nothing in the benchmark and loses the feedback a costly job deserves.
- Keep `start_discussion` and stop the run after its call. Fixes the trailing text, but keeps the rejected-call retries and their cost.
